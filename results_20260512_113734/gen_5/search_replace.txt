<DESCRIPTION>
The primary issue is that val_slope (0.006) is only 8.2% of train_slope (0.074), indicating severe regime-specific overfitting. The model learns patterns that work in the training period but collapse in validation.

My strategy addresses this through three targeted changes:

1. **Reduce lookback windows**: Current features use 20-60+ bar windows. I'll shift to 5-20 bar windows for most features. Shorter windows adapt faster to regime changes and reduce temporal overfitting.

2. **Add rolling z-score normalization**: Instead of raw returns and volatility levels, I'll normalize key features within rolling windows. A 1% move means different things in different volatility regimes. Z-scoring makes features regime-invariant.

3. **Increase regularization and reduce model complexity**: I'll reduce n_estimators from 400→250, increase min_child_weight from 1→5, and add moderate L1/L2 regularization. This forces the model to learn only the most robust patterns that generalize across regimes.

4. **Add rate-of-change features**: Instead of absolute volatility levels, I'll add features measuring how quickly volatility and autocorrelation are changing. These "meta-features" capture regime transitions rather than regime states.

The combination should preserve train_DA while significantly improving val_slope from 0.006 toward 0.020+, which is the primary objective.
