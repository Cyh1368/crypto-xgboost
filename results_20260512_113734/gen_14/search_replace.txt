<DESCRIPTION>
The core issue is the val_slope collapsing to 0.0039 (7% of train slope), indicating severe regime-specific overfitting. The feedback specifically mentions that features work train→test but break at test→val boundary, suggesting a second regime shift.

My strategy addresses this through three coordinated changes:

1. **Shorter lookback windows (5-20 bars instead of 60+)**: Market microstructure at 15-minute resolution changes rapidly. Features based on 60+ bars are learning patterns that won't persist. I'll reduce the maximum lookback from 60 to 20 for volatility and regime features.

2. **Z-score normalization within rolling windows**: Instead of absolute values, I'll express features as z-scores within recent windows. A 1% move means different things in high vs low volatility regimes. This makes features regime-invariant.

3. **Rate-of-change features for market character**: Rather than just measuring current volatility or trend strength, I'll add features that capture HOW these are changing - volatility trend, autocorrelation trend, efficiency ratio trend. These measure regime transitions rather than regime states.

4. **Reduce model complexity**: The current model has high regularization (reg_alpha=0.5, reg_lambda=2.0, gamma=0.1) AND 650 estimators, which is causing prediction collapse (pred_std_ratio=0.086). I'll reduce n_estimators to 300, remove gamma, and lower regularization to allow the model to be more expressive while still learning robust patterns through shorter lookbacks.

5. **Feature interaction: momentum × volatility_regime**: Adding a single multiplicative term often generalizes better than both features separately, as it captures the joint state space.

These changes work together: shorter lookbacks decay faster but generalize better, z-scores make them regime-invariant, rate-of-change features capture transitions, reduced regularization allows expression, and the interaction term captures joint behavior.
