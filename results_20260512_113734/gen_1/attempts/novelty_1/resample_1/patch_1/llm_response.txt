<DESCRIPTION>
The primary issue is that val_slope (0.006) is only 8.2% of train_slope (0.074), indicating severe regime-specific overfitting. The model learns patterns from the training period that don't generalize to the validation period.

My strategy addresses this through three coordinated changes:

1. **Shorter lookback windows**: Replace long lookbacks (60, 200 bars) with shorter ones (5-20 bars). Shorter windows decay faster but are more regime-invariant because they capture recent dynamics rather than historical regimes.

2. **Z-score normalization within rolling windows**: Instead of raw returns or volatility levels, compute z-scores relative to recent history. This makes features regime-invariant - a "high" momentum means the same thing in low-vol and high-vol regimes.

3. **Regularization to prevent overfitting**: Increase min_child_weight from 1 to 5 and reduce n_estimators from 400 to 250. This forces the model to learn only robust, high-sample patterns rather than regime-specific noise.

4. **Rate-of-change features**: Add features that measure how market character is CHANGING (vol_trend, autocorr_trend) rather than absolute levels. These tend to be more stable across regimes.

The key insight is that absolute feature values (e.g., "volatility = 0.02") are regime-specific, but normalized deviations (e.g., "volatility is 1.5 std above its 20-bar mean") generalize better.

Expected improvements:
- val_slope should increase from 0.006 to >0.020 as features become more regime-invariant
- val_r should increase from 0.054 to >0.080
- pred_std_ratio should increase from 0.112 to >0.18 as the model makes bolder predictions
- overfit_gap should decrease as regularization prevents regime-specific fitting
