<DESCRIPTION>
The current program shows a critical problem: val_slope is only 5.2% of train_slope, indicating severe regime-specific overfitting. The model learns patterns that work in training but collapse in validation. The best-performing prior program achieved 96.0% generalization ratio by using regime-conditional features.

The key insight is that momentum, efficiency, and autocorrelation features should be explicitly modulated by volatility regime indicators. Instead of treating these features as static, we create regime-conditional versions that adapt to market conditions:

1. **High-volatility momentum features**: Multiply short-term returns by a high-vol indicator (vol_regime_rank > 0.7). In high-vol regimes, momentum patterns are stronger and more reliable.

2. **Low-volatility efficiency features**: Multiply efficiency by a low-vol indicator (vol_regime_rank < 0.3). In low-vol regimes, mean reversion and efficiency patterns dominate.

3. **Regime-specific autocorrelation**: Create separate autocorrelation features for high and low volatility periods, as persistence patterns differ dramatically across regimes.

This approach directly addresses the regime shift problem by making features explicitly regime-aware rather than assuming static relationships. The vol_regime_rank feature already exists in the codebase, so we can leverage it immediately.

Additionally, I'll reduce regularization slightly (reg_lambda from 0.5 to 0.4) to allow the model to learn these more nuanced regime-conditional patterns without being overly constrained.
</DESCRIPTION>
