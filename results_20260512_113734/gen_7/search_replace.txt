The primary issue is that val_slope collapsed to -0.0009 (from 0.0217 on train), indicating severe regime shift between test and val periods. The current regularization (reg_alpha=0.4, reg_lambda=1.2, min_child_weight=5) is too aggressive and causing prediction collapse (pred_std_ratio=0.0528, far below target of 0.18).

My strategy addresses three core problems:

1. **Reduce lookback windows**: Long lookbacks (60, 200 bars) encode regime-specific patterns. I'll shift toward 5-20 bar windows that capture price action dynamics while being more regime-invariant.

2. **Add z-score normalization within rolling windows**: Instead of using raw values, normalize features within their recent distribution. A 2% return in low-vol regime vs high-vol regime has different meanings - z-scoring makes this regime-invariant.

3. **Add rate-of-change features**: The warning explicitly states we need features measuring "CHANGE in market character" not just current state. I'll add:
   - vol_trend: is volatility accelerating/decelerating?
   - autocorr_trend: is serial correlation changing?
   - efficiency_trend: is market becoming more/less efficient?

4. **Relax regularization**: The collapse penalty (1.177) and pred_std_ratio (0.0528) show over-regularization. I'll reduce reg_alpha/reg_lambda and min_child_weight to allow the model to express variance while relying on shorter lookbacks for generalization.

5. **Add momentum×volatility_regime interaction**: This single multiplicative term often generalizes better than both features separately, as suggested in the prompt.

The feature count will stay under 80 by being selective about which features to keep and which to remove.
