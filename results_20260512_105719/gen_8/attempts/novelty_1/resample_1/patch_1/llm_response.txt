<DESCRIPTION>
The primary issue is that val_slope (0.006) is only 8.2% of train_slope (0.074), indicating severe regime-specific overfitting. The model learns patterns that don't generalize to the validation period.

My strategy addresses this through three complementary changes:

1. **Shorter lookback windows**: Replace long lookbacks (60, 200 bars) with shorter ones (5-20 bars). Shorter windows adapt faster to regime changes and reduce the chance of learning stale patterns. This directly addresses the feedback about "shorter lookbacks."

2. **Z-score normalization within rolling windows**: Instead of using raw volatility or momentum values, I'll normalize them by their recent distribution. A 1% move in a low-vol regime is very different from a 1% move in high-vol. Z-scoring makes features regime-invariant. This is explicitly recommended in the feedback.

3. **Rate-of-change features**: Add features that measure HOW market character is changing (vol_acceleration, momentum_trend) rather than absolute levels. These capture regime transitions better than static regime indicators.

4. **Reduce model complexity**: Cut n_estimators from 400 to 250 and increase min_child_weight from 1 to 3. This forces the model to learn only the most robust patterns with sufficient sample support, reducing overfitting to training-specific noise.

5. **Feature interaction simplification**: Keep only the most generalizable interaction (momentum × vol_regime) and remove complex multi-way interactions that likely overfit.

These changes should improve val_slope from 0.006 toward the target of 0.020+ while maintaining or improving directional accuracy.
