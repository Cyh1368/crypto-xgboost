regime_boosted_features
</NAME>

<DESCRIPTION>
This edit aims to reduce prediction collapse by adding a small set of higher-signal, regime-aware features while keeping the feature count under the 80-feature cap. The current feature set is already decent on DA but still too mean-reverting in prediction space (`pred_std_ratio` is low). To address that, I’m adding:

- shorter-horizon return acceleration and trend persistence features
- normalized breakout / compression indicators
- a couple of regime interaction terms that let XGBoost separate trend-following from mean-reversion conditions more cleanly
- a lightweight “intrabar position vs volatility” feature that often helps perpetual futures on 15m bars

All of these are past-only and explicitly shifted where needed. This should give the model more expressive separation without violating the no-lookahead constraint. I also leave the feature count safely below 80 by slightly trimming redundant windows.
</DESCRIPTION>

less_regularized_xgb
</NAME>

<DESCRIPTION>
This edit makes the tree ensemble more expressive and slightly less constrained so it can move away from the mean more often. The current metrics show acceptable DA but very low prediction dispersion, which is exactly the situation where a modest reduction in regularization and a bit more boosting capacity can help.

I’m making the following changes:
- slightly deeper trees and more estimators
- lower `min_child_weight`
- reduce `reg_alpha` and `reg_lambda`
- add a small `gamma` to avoid noisy splits while still allowing enough flexibility
- lower learning rate a bit for smoother fit with more trees
- reduce clipping aggressiveness from 98.0 to 98.5 so the model sees a slightly wider target range

This is a targeted attempt to improve `pred_std_ratio` without materially increasing overfit risk.
</DESCRIPTION>
