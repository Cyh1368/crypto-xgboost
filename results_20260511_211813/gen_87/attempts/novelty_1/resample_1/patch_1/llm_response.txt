Looking at the performance metrics across all prior attempts, I can see a consistent pattern:

1. **Collapse penalty is the dominant issue** (0.41-0.62): The model is predicting too close to the mean, with `pred_std_ratio` stuck in the 0.03-0.07 range despite various regularization adjustments.

2. **Overfit gap is growing** (0.056 in current): The train_DA (0.573) is significantly ahead of val_DA (0.517), suggesting the model is learning noise rather than signal.

3. **The feature set is bloated**: With 60+ features, many of which are redundant (multiple regime interactions, multiple momentum accelerations), the model struggles to find true signal.

4. **Regularization paradox**: Reducing regularization (reg_lambda from 0.02→0.005) helped slightly but didn't solve the core issue. The problem isn't just regularization—it's that the signal-to-noise ratio in the features is poor.

## Root Cause Analysis

The current approach adds more interaction features hoping to capture suppressed signals, but this actually:
- Increases dimensionality without improving signal quality
- Makes regularization harder to tune (need to balance many weak signals)
- Causes the model to average predictions toward zero when no strong signal exists

## Solution Strategy

I'll implement a **three-pronged approach**:

1. **Aggressive feature pruning**: Keep only the highest-quality, most orthogonal features
2. **Stronger regularization with better hyperparameters**: Use L1 (alpha) to force feature selection, combined with higher lambda
3. **Simpler, cleaner feature engineering**: Focus on core momentum/volatility/regime signals without redundant interactions

The key insight: **pred_std_ratio improves when the model has fewer, higher-quality features to work with**, because it can make confident predictions on the strongest signals rather than averaging weak ones.
